    ဒီကွန်ပိုင်း အောင်မြင်ပြီးနောက် ဆက်တင်များတွင် ယခင်က ဖွင့်ထားပါက အသံနှင့် ဒိုင်ယာလော့ အသိပေးချက် ရှိမည်။

    3. လိုအပ်ပါက အလိုအလျောက် လက်မှတ်ထိုးခြင်းကိုလည်း သတ်မှတ်နိုင်သည်။

    ပြီးဆုံးသည့်အခါ မှတ်တမ်း ရပ်မည် (မြင်ရမည်)။

    အောက်တွင် တည်ဆောက်ထားသော အက်ပ်ကို ချက်ချင်း တပ်ဆင်ရန်လည်း တောင်းဆိုမည်။
    တည်ဆောက်ပြီးနောက် အက်ပ်ကို မည်သည့်နေရာတွင် သိမ်းသနည်း?
    ဖြုတ်ထားသော အက်ပ်ဖိုလ်ဒါသို့။ ပရောဂျက် အမြစ်တွင် (apktool.json ဘေး)
    ဖိုင်များစွာကို တပြိုင်နက် ဒီကွန်ပိုင်းနိုင်ပါသလား?

    မည်သို့ လုပ်မည်နည်း?
    ဖိုင်များစွာ ရွေးပြီး ကြာကြာ နှိပ်၍ မီနူးဖွင့်ပါ။
    သတိ! ဤသည် တူညီသော အမျိုးအစား ဖိုင်များအတွက် အလုပ်လုပ်သည်။ apk မဟုတ်သော အရာ ရွေးထားပါက မီနူးတွင် အချက်များ ရှိမည် မဟုတ်။
    apk များ သိမ်းမည့် ဖိုလ်ဒါကို မည်သို့ ပြောင်းမည်နည်း?
    1. ဆက်တင်များ → «တည်ဆောက်ခြင်းနှင့် ဒီကွန်ပိုင်း» → «တပ်ဆင်ထားသော အက်ပ်များ၏ အထွက် ဒါရိုက်ထရီ သတ်မှတ်»
    2. လိုချင်သော ဖိုလ်ဒါသို့ သွားပါ၊ «လမ်းကြောင်း» စာကြောင်းကို နှိပ်၍ အထွက် ဒါရိုက်ထရီ သတ်မှတ်ပါ။
    3. ဖိုင်မန်နေဂျာတွင် တိုက်ရိုက် အထွက်ဖိုလ်ဒါ သတ်မှတ်နိုင်သည်။
    «တပ်ဆင်ထားသော အက်ပ်များ၏ အထွက် ဒါရိုက်ထရီ» အချက်ဆိုသည်မှာ?
    အက်ပ်များ မီနူးမှ ဆက်လက် လုပ်ဆောင်ရန် APK များကို ထုတ်ယူ/ထုတ်ပို့မည့် ဒါရိုက်ထရီ ဖြစ်သည်။
    «.apk» ဖိုင်တွင် အရင်းအမြစ်များကို မည်သို့ အစားထိုးမည်နည်း?
    ပထမ ဒီကွန်ပိုင်းပြီး ဖိုင်များ ကူးယူ/ကူးထည့်ကာ တည်ဆောက်ပါ။
    အမှားမရှိဘဲ လုပ်ခဲ့သော်လည်း အက်ပ် မတည်ဆောက်ပါက၊ သို့မဟုတ် apk တွင် ဘာမှ မပြောင်းဘဲ ပြန်စုစည်းရုံသာ ဆိုလျှင် ဘာလုပ်ရမည်နည်း?
    aapt ဗားရှင်းကို ပြောင်းပါ။
    Warning ဖြစ်ရပ်အဆင့်အတွက် မှတ်တမ်းကို ကြည့်ပါ။
    ယေဘုယျအားဖြင့် မှတ်တမ်းကို ကြည့်ပါ — အကြောင်းရင်း ဖော်ပြထားသင့်သည်။
    Apktool ပရောဂျက်များနှင့် ကိုက်ညီမှုက ဘယ်လိုလဲ?
    Apktool M သည် ပုံမှန် Apktool မှ ခွဲခြမ်းသည့် ပရောဂျက်များကို တည်ဆောက်ခွင့်ပြုသည်။
    တည်ဆောက်မီ Apktool M သည် .yml ကို .json သို့ ပြောင်းသည်။
    မှတ်တမ်းဖြင့် လုပ်ငန်းစဉ် အချက်အလက်ကို စောင့်ကြည့်နိုင်သည်။
    Apktool M သည် စနစ်အက်ပ်များနှင့် အလုပ်လုပ်နိုင်ပါသလား?
    ဟုတ်ကဲ့၊ ဖြစ်နိုင်သည်။

    မည်သို့ လုပ်မည်နည်း?
    ထိုကဲ့သို့ apk များနှင့် မလုပ်မီ ဤ apk ၏ ဆက်စပ်မီနူး အချက်ဖြင့် apk ဖရိမ်းဝက်များကို တင်သွင်းရမည်။ တင်သွင်းခြင်းကို ထိုကဲ့သို့ apk အားလုံးတွင် ပြုလုပ်သည်။

    အခြေခံလမ်းကြောင်း: /system/framework/..

    ၎င်းတို့သည် /system/vendor/framework စသည် ကပ်လျက် ဒါရိုက်ထရီများတွင်လည်း ရှိနိုင်သည်။ ထိုဒါရိုက်ထရီများ ရှိပါက (ရှားပါးသည်)။

    ဖရိမ်းဝက် ဥပမာ:

    ထို့နောက် ပုံမှန် apk ကဲ့သို့ ဒီကွန်ပိုင်းနှင့် စုစည်းပါ။ မူရင်း META-INF နှင့် manifest ကို သိမ်းရန် ဒီကွန်ပိုင်း ဆက်တင်များတွင် «မူရင်းနှင့် ကိုက်ညီ» ရေဒီယိုခလုတ်ကို ဖွင့်ပါ။

    «တည်ဆောက်ခြင်းနှင့် ဒီကွန်ပိုင်း» ကဏ္ဍရှိ အချက်များ ရှင်းလင်းချက်
    အထွက်ဖိုလ်ဒါ
    «အက်ပ်များ» တဘ်မှ တပ်ဆင်ထားသော အက်ပ်များကို ထုတ်ယူ/ထုတ်ပို့မည့် လမ်းကြောင်း။
    aapt2 အသုံးပြု
    တည်ဆောက်မီ aapt ဗားရှင်း ရွေးချယ်အချက်သို့ ကိရိယာ၏ ဒုတိယဗားရှင်းကို ထည့်သည်။
    ဒီဘတ် အချက်အလက်

    တည်ဆောက်စဉ် ဒီဘတ်ဒေတာကို Smali ဖိုင်များတွင် သိမ်းသည်၊ ဥပမာ.line, .paramစသည်။

    မှတ်ချက်:
    ဤဒေတာသည် ဒီဘတ်လုပ်နိုင်သော မုဒ်တွင် အက်ပ် ဒီဘတ်လုပ်ရန်သာ လိုအပ်သည်။ ထို့အပြင် Logcat တွင် Smali ပျက်ကျမှုများကို အနီးကပ် ဒီဘတ်လုပ်ရန် (ရှားပါး၊ ပျက်ကျစေသော စာကြောင်းသို့ ကျောက်ဆူးအဖြစ် ကူညီနိုင်သည်)။ ၎င်းတို့သည် ကုဒ် အကောင်အထည်ဖော်မှုကို မထိခိုက်ပါ။ Smali assembler တည်းဖြတ်ရာတွင် ရည်ညွှန်းမှတ်များအဖြစ်လည်း ကူညီနိုင်သည် (မော်ဒယ်လ်များအတွက်)။
    ဒီဘတ်မုဒ်
    ရေးသည် <application /> manifest ရှိ တဂ်အတွင်း အရည်အချင်း တန်ဖိုးကို android:debuggable သို့ true။ စနစ်အား ၎င်းသည် ဒီဘတ်အက်ပ်ဖြစ်ကြောင်း အသိပေးသည်။ ဤအက်ပ်၏ မှတ်တမ်းသို့ ဝင်ရောက်ခွင့်ကို တိုးချဲ့နိုင်သည်။ ဤလုပ်ဆောင်ချက်နှင့် အပြန်အလှန်ဆက်သွယ်မှုသည် အထူးကိရိယာများ (Android Studio နှင့် ADB အဆင့် ဒီဘတ် စသည်) ဖြင့်သာ ဖြစ်နိုင်သည်။ ဤရွေးချယ်မှုသည် Logcat နှင့် မသက်ဆိုင် — ဤပါရာမီတာ ပြောင်းလျှင် စနစ်မှတ်တမ်းရှိ ဒီဘတ် မှတ်တမ်းအရေအတွက် မပြောင်းပါ။

    ထိုကဲ့သို့ အက်ပ်ကို လက်ရှိ ဒီဘတ်အတွက် သတ်မှတ်ရန် «စနစ်ဆက်တင်များ» ဆော့ဖ်ဝဲရေးသားသူများ «ဒီဘတ်အက်ပ်» တွင် ရွေးပါ (လမ်းကြောင်းများ ကွာခြားနိုင်သည်)။

    အပြည့်
    တည်ဆောက်စဉ် ဖိုင်တစ်ခုချင်းစီ စုစည်းပြီးနောက် နောက်ဆုံးအခြေအနေကို မှတ်တမ်းသို့ ထုတ်သည်။ မလိုပါက မဖွင့်ပါနှင့်။
    မူရင်းနှင့် ကိုက်ညီ
    မူရင်း အရင်းအမြစ် ဟက်ရှ်များကို လေးစားခြင်းဖြင့် မူရင်း META-INF နှင့် manifest ဟက်ရှ်ကို သိမ်းနိုင်သည်။
    ဤမုဒ်သည် Smali သာ တည်းဖြတ်ခွင့်ပြုသည် — res/... ရှိ တည်းဖြတ်ထားသော ဖိုင်ကို တည်ဆောက်ရန် ကြိုးစားပါက မူရင်း ဟက်ရှ်နှင့် မကိုက်ညီသောကြောင့် (ပြင်ဆင်ပြီး) နောက်ဆုံး apk မှ ဖျက်မည်။

    ဤမေးခွန်းကို ရှင်းလင်းရန် လိုသည်။

    Smalisedit အားလုံး ခွဲခြမ်းစိတ်ဖြာ
    Smali တွင် ဖိုင်ခွဲခြမ်းစိတ်ဖြာမှုကို မြန်စေသည်။
    «APKTOOL_DUMMY» ထည့်ရန်

    ပုံသေအားဖြင့် resources.arsc အတွင်း အရင်းအမြစ် ID များကို ဂဏန်းသင်္ချာ တိုးတက်မှုဖြင့် သတ်မှတ်သည်။ အချို့အခြေအနေတွင် ပျက်နိုင်သည် — တန်ဖိုးအမျိုးအစားများအတွင်း အချို့နေရာများ မဖြည့်ရသေး (မသုံးရသေး)။

    ထိုနေရာများကို တိုးတက်မှု ပြည့်စုံမှု ပြန်လည်ရရှိရန် APKTOOL_DUMMY stub ဖြင့် ဖြည့်သည်။ ဤစာကြောင်းများကို မည်သူမျှ မသုံးဘဲ ဘာကိုမှ မထိခိုက်ပါ။

    အသေးစား မှတ်ချက်:

    res/values/public.xml မှ အရင်းအမြစ် အရာဝတ္ထုကို ဖျက်ပါက တည်ဆောက်စဉ် ထိုကဲ့သို့ နေရာလွတ်ကို ရှာပြီး ၎င်း၏ ID ကို ထိုတွင် သတ်မှတ်ရန် ကြိုးစားမည်။ နေရာမရှိပါက ၎င်း၏ အမျိုးအစား စာရင်းအဆုံးတွင် ထည့်မည်။ Smali တွင် သတ်မှတ်ထားသော အရာဝတ္ထု ID များနှင့် ဤသို့ မလုပ်ရန် အကြံပြုသည် — ID ဖြင့် သတ်မှတ်ထားသော အရင်းအမြစ် ရွှေ့ပြီးသောကြောင့် (ထိုကဲ့သို့ မရှိတော့) ပျက်ကျမည်။

    public.xml ကို ဖျက်ခြင်းက Apktool အား တိုးတက်မှုကို အစမှ ဖန်တီးစေမည် — ထိုအခါ စတင်နှင့် ပိတ် ID ကြား နေရာလွတ် မရှိသောကြောင့် APKTOOL_DUMMY ကို မည်သည့်နေရာတွင်မျှ ထည့်မည် မဟုတ်။

    APKTOOL_DUMMY လိုအပ်မှုကို အသုံးပြုသူကသာ ဆုံးဖြတ်သည်။ ဒီကွန်ပိုင်းထားသော ပရောဂျက်တွင် ID များအကြား သီးခြား ဖွဲ့စည်းပုံ ရှိပါကလည်း လိုအပ်နိုင်သည် (အထူးသဖြင့် စိတ်ကြိုက် အရည်အချင်းများနှင့်/သို့မဟုတ် ရှုပ်ထွေးအောင် ပြုလုပ်ခြင်းကြောင့်)။

    HTML ပုံစံချ
    .html နှင့် .htm (?) ဖိုင်အားလုံး၏ အကြောင်းအရာကို XML စနစ်ကျနမှုအတိုင်း ပုံစံချမည်။ HTML စာမျက်နှာ ပြသမှုကို ပျက်စေနိုင်သည်။ လိုအပ်မှသာ ထည့်ပါ။
    «build» ဖိုလ်ဒါ ဖျက်ရန်

    တည်ဆောက်စဉ် DEX နှင့် ARSC ဖိုင်များကို build ဖိုလ်ဒါတွင် ကက်ရှ်လုပ်သည်။ ယခင် တည်ဆောက်ပြီးနောက် အရင်းအမြစ်များ မပြောင်းဘဲ apk ကို ပြန်တည်ဆောက်ပါက .arsc ကို ပြန်မဖန်တီးဘဲ ဟက်ရှ် တူညီသောကြောင့် (မပြင်ဆင်) ကက်ရှ်မှ ယူမည်။ Smali (DEX ဖိုင်များ) နှင့်လည်း သက်ဆိုင်သည်။ ပြန်စုစည်းမှု ကျော်ခြင်းဖြင့် apk တည်ဆောက်မှု မြန်စေသည်။

    ဖိုလ်ဒါ ဖျက်ခြင်းသည် နေရာလွတ် ဖန်တီးရုံသာ ဖြစ်သည်။ ထို့နောက် နောက်တည်ဆောက်မှုတွင် .dex နှင့် .arsc ကို «အစမှ» ပြန်ဖန်တီးပြီး ဖိုလ်ဒါကို ပြန်ဖန်တီးမည်။ ဤရွေးချယ်မှုကို ဖွင့်ပါက အောင်မြင်သော တည်ဆောက်ပြီးနောက် ဖိုလ်ဒါကို အလိုအလျောက် ဖျက်နိုင်သည်။ လိုချင်ပါက ဖွင့်ပါ။
