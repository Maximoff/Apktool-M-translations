    クイック編集とは何ですか？
    デコンパイルと再ビルドをせずに、アプリの主要なデータの一部を編集することです。
    クイック編集は何に使いますか？
  • アプリ（apk）の情報、権限、優先インストール先を表示する（実際のインストール先と混同しないでください）;
  • アプリ名を変更する;
  • アプリのパッケージ名を変更する（アプリを複製する）;
  • アプリ内のベクター（自動生成）、アダプティブ、通常のラスターアイコンを置き換える;
  • アプリの優先インストール先を設定する;
  • 最小またはターゲット SDK バージョンを変更する;
  • アプリを Android TV 向けに適応させる;
  • Manifest から削除する: android:isSplitRequired, android:debuggable, android:testOnly.
    • 「権限」項目は何のためですか？
    アプリの権限を表示し、有効または無効にするためです。
    画像をベクターに変換できますか？
    はい。
    PNG、Jpeg、Webp、Svg 形式に対応しています。
    変換には次を使用します {old file name}type _vector.xml
    変換時に画質を上げたり下げたりできます。
    svg 画像を VectorDrawable に変換できますか？
    はい。
    未コンパイルの SVG/VectorDrawable ポリゴンのプレビューで利用できます
    注意: svg は単純で適切な構造である必要があります。そうでないとパーサーが正しく処理できず、動作させるために手動で正規化する必要があります。
    ビットマップ画像を VectorDrawable に変換できますか？
    はい。
    万能ではありません。トレース誤差が大きくなることがあり、元画像の形状の複雑さに依存します。
    アプリアイコンを置き換えるには？
    1. 必要なアイコンを用意します。できれば png 形式で、サイズは 192x192px 以下が望ましいです。
    2. 対象アプリを選択 → クイック編集。
    3. 左上にインストール済みアプリのアイコンと名前が表示されます。
    4. アイコン自体をタップし、用意したアイコンを選択します。
    5. 必要に応じて設定をオンにします: 「アダプティブアイコンを置き換える」「高品質アイコン（大きいサイズ）」
    6. 以前にインストールしていなければ、署名ファイルも選択します。
    7. 「保存」をタップします。
    完成ファイルは同じフォルダー内、選択したアプリの横に、末尾に mod ラベル付きで置かれます。
    アプリアイコンを抽出するには？
    1. 対象アプリを選択 → クイック編集。
    2. アイコンを長押しします。
    抽出したアイコンは同じフォルダー内、選択したアプリの横に置かれます。
    最小またはターゲット sdk バージョンを変更するには？
    1. 対象アプリを選択 → クイック編集。
    2. 「最小 SDK バージョン」または「ターゲット SDK バージョン」の設定で必要な変更をします。
    3. 「保存」をタップします。
    完成ファイルは同じフォルダー内、選択したアプリの横に、末尾に mod ラベル付きで置かれます。
    アプリ名を変更するには？
    1. 対象アプリを選択 → クイック編集。
    2. 次に、目的のアプリ名を必要な名前に変更します。
    3. 以前にインストールしていなければ、署名ファイルを選択します。
    4. 「保存」をタップします。
    完成ファイルは選択したアプリの横に、末尾に mod 付きで置かれます。
    「アプリ名」を変更できないのはなぜですか？（項目が無効です。）
    おそらくアプリの最小 sdk バージョンがシステムのバージョンより高いためです。この条件では編集が制限されます。
    まず最小 sdk バージョンを下げてから、ほかを編集してください。
    アプリのパッケージ名を変更するには？
    1. 対象アプリを選択 → 「クイック編集」。
    2. 次にパッケージ名を変更します。
    3. 以前にインストールしていなければ、署名ファイルを選択します。
    4. 「保存」をタップします。
    完成ファイルは選択したアプリの横に、末尾に mod 付きで置かれます。
    このアプリで apk のクローンを作るには？
    1. 対象アプリを選択 → 「クイック編集」。
    2. 次にパッケージ名を変更します。たとえば名前の末尾の文字を追加または削除します。
    3. 以前にインストールしていなければ、署名ファイルを選択します。
    4. 「保存」をタップします。
    完成ファイルは選択したアプリの横に、末尾に mod 付きで置かれます。
    クイック編集中にアプリをクローンするには？
    プログラムはクイック編集時に次のパラメータを変更します: AndroidManifest.xml と resources.arsc。
    アプリを Android TV 向けに適応させるには？
    1. 対象アプリを選択 → 「クイック編集」。
    2. 次に「Android TV 向けに適応」のチェックをオンにします。
    3. 以前にインストールしていなければ、署名ファイルを選択します。
    4. 「保存」をタップします。
    完成ファイルは選択したアプリの横に、末尾に mod 付きで置かれます。アプリアイコンがバナーとして使われます。
    クイック編集後にアプリがインストールできない場合は？
    パッケージに署名し忘れていないか確認してください。
    クイック編集で署名を選択します。以前に署名を使っていなければ、既定では「署名しない」を選びます。
    完全編集 - デコンパイルとビルド
    デコンパイルとは何で、何に使いますか？
    arsc+dex のデコンパイルはバイナリコードを人が読める形式に変換します。アプリ資源（resources.arsc）と Smali アセンブラ（コード）の編集に必要です。また、情報へのアクセス、パッチ適用、翻訳など、このデコンパイルが必要な機能にも使います...

    再コンパイルには aapt のバイナリが必要です。インストール要求はアプリ初回起動時に表示されます。していなければ、「設定」ビルドとデコンパイル「ツールの置換」…用にダウンロード、で行います。

    アプリをデコンパイルするには？
    1. 対象アプリを選択します。
    2. タップします。
    3. ポップアップメニューが開きます。
    4. 「デコンパイル」を選択します。
    5. デコンパイルする項目をマークします:
      • 「資源をデコンパイル」
      • 「classes.dex をデコンパイル」または「すべての *.dex ファイルをデコンパイル」。
        （「すべての *.dex」は入れ子フォルダー内の dex、たとえば assets、mthook などを担当します。）
      • 必要なら「追加資源のデコンパイル」でデコンパイル先も選べます。
    デコンパイルが成功すると、設定で以前有効にしていれば音声とダイアログの通知があります。
    アプリを再コンパイルするには？
    1. プロジェクト内で、エクスプローラーウィンドウの上の「プロジェクトをビルド」ラベルをタップします。
    2. ビルドウィンドウで資源ビルドツール aapt または aapt2 を選択します。
    3. 必要なら自動署名も指定できます。
    ログはリアルタイムで表示されます。ビルド中の段階、コメント、エラーを追跡できます。
    完了するとログが止まります（それが分かります）。
    コンパイルが成功すると、設定で以前有効にしていれば音声とダイアログの通知があります。
    下部では、ビルドしたアプリをすぐにインストールするかも尋ねられます。
    ビルド後、アプリはどこに保存されますか？
    分解したアプリのフォルダーへ。プロジェクトルート（apktool.json の横）
    複数ファイルを同時にデコンパイルできますか？
    はい。ただし同時だとメモリが足りないことがあるので、連続してデコンパイルした方がよいです。

    どうすればよいですか？
    複数ファイルを選択し、長押しでメニューを開きます。
    注意！ 同じ種類のファイルで機能します。apk 以外が選択されていると、メニューに項目が出ません。
    apk の保存先フォルダーを変更するには？
    1. 設定 → 「ビルドとデコンパイル」 → 「インストール済みアプリの出力ディレクトリを設定」
    2. 目的のフォルダーに行き、「パス」行をタップして出力ディレクトリを設定します。
    3. ファイルマネージャーで直接出力フォルダーを設定することもできます。
    「インストール済みアプリの出力ディレクトリ」項目とは？
    アプリメニューから、以降の作業のために APK をエクスポート／抽出するディレクトリです。
    「.apk」ファイル内の資源を置き換えるには？
    まずデコンパイルし、ファイルをコピー／貼り付けてビルドします。
    エラーなく作業したのにアプリがビルドされない、または apk を何も変えず再コンパイルしただけの場合は？
    aapt のバージョンを切り替えてください。
    ログの Warning イベントレベルを確認してください。
    一般にログを見てください。原因が示されているはずです。
    通常の Apktool プロジェクトとの互換性は？
    Apktool M は通常の Apktool で解析されたプロジェクトをビルドできます。
    ビルド前に Apktool M は .yml を .json に変換します。
    ログで処理情報を追跡できます。
    Apktool M はシステムアプリを扱えますか？
    はい、可能です。

    どうすればよいですか？
    そのような apk を扱う前に、その apk のコンテキストメニュー項目で apk フレームワークをインポートする必要があります。インポートはそのような apk すべてに対して行います。

    基本パス: /system/framework/..

    /system/vendor/framework など隣接ディレクトリにもある場合があります。それらのディレクトリがある場合（まれです）。

    その後、通常の apk と同様にデコンパイルとコンパイルをします。元の META-INF と manifest を残すには、デコンパイル設定で「オリジナルに合わせる」ラジオボタンを有効にします。

    「ビルドとデコンパイル」セクションの項目の説明
    出力フォルダー
    「アプリ」タブからインストール済みアプリをエクスポート／抽出するパスです。
    aapt2 を使用
    ビルド前の aapt バージョン選択項目に、ツールの第2バージョンを追加します。
    デバッグ情報

    ビルド時、デバッグデータは Smali ファイルに保存されます。例:.line, .paramなど。

    注意:
    このデータはデバッグ可能モードでのアプリデバッグ専用です。また Logcat での Smali クラッシュのピンポイントデバッグにも使えます（まれ。クラッシュ原因の行のアンカーになります）。コード実行には影響しません。モデラーが Smali アセンブラを編集するときの参照点にもなります。
    デバッグモード
    書き込みます <application /> manifest のタグ内の属性値を android:debuggable へ true。システムにデバッグアプリであることを通知します。このアプリのログへのアクセスを広げられます。機能の操作は専用ツール（Android Studio や ADB レベルのデバッグなど）でのみ可能です。このオプションは Logcat には適用されません。このパラメータを変えてもシステムログのデバッグエントリ数は変わりません。

    そのようなアプリを現在のデバッグ対象にするには、「システム設定」開発者向け「デバッグアプリ」で選択します（パスは異なる場合があります）。

    完全
    ビルド中、各ファイルのコンパイル後の最終状態をログに出力します。不要なら有効にしないでください。
    オリジナルに合わせる
    元の資源ハッシュを尊重することで、元の META-INF と manifest のハッシュを保存できます。
    このモードでは Smali のみ編集できます。res/... の編集ファイルをビルドしようとすると、元のハッシュと一致しない（変更済み）ため最終 apk から削除されます。

    この質問は明確化が必要です。

    すべての Smalisedit の解析
    Smali のファイル解析を高速化します。
    「APKTOOL_DUMMY」を追加

    既定では resources.arsc 内の資源 ID は等差数列で設定されます。壊れている場合があり、値タイプ内の一部が未記入（空き）のことがあります。

    それらの場所は数列の整合性を戻すために APKTOOL_DUMMY スタブで埋められます。これらの行は誰も使わず、何にも影響しません。

    簡単な注記:

    res/values/public.xml から資源オブジェクトを削除すると、ビルド時にそのような空きを探してそこに ID を設定しようとします。空きがなければ、そのカテゴリの項目リストの末尾に追加されます。Smali で指定されているオブジェクト ID では推奨しません。ID で指定された資源が移動済み（もはや存在しない）ためクラッシュします。

    public.xml を削除すると、Apktool は数列をゼロから作ります。開始 ID と終了 ID の間に空きがないため APKTOOL_DUMMY はどこにも入りません。

    APKTOOL_DUMMY の要否はユーザーが決めます。デコンパイルしたプロジェクトの ID 構造が特殊な場合（カスタム属性や難読化など）にも必要になることがあります。

    HTML を整形
    すべての .html および .htm（?）ファイルの内容が XML 構文に従って整形されます。HTML ページの表示が崩れることがあります。必要なときだけ入れてください。
    「build」フォルダーを削除

    ビルド中、DEX と ARSC ファイルは build フォルダーにキャッシュされます。前回のビルド後に資源を変えていなければ、再ビルド時に .arsc は再作成されず、ハッシュが同一（未変更）のためキャッシュから使われます。Smali（DEX ファイル）も同様です。再コンパイルを省略して apk ビルドを速くします。

    フォルダー削除は空き容量を増やすだけです。その後のビルドでは .dex と .arsc が「ゼロから」再作成され、フォルダーも再作成されます。このオプションを有効にすると、成功したビルドの後でフォルダーを自動削除できます。必要なら有効にしてください。

    すべて出力ディレクトリへ
    正常にコンパイルされた apk はすべて、上記の出力ディレクトリへ自動的に移されます。
    フレームワークの管理
    外部からインポートしたフレームワークを管理できます。リセットボタンは一覧とファイルをローカルで消し、Apktool M から res-framework.apk（ID 1）も復元します。
    アプリの翻訳
    翻訳で何言語がサポートされていますか？
    100 言語以上です。
    Yandex.Translate で使えるオプションは？
  • 資源（strings、arrays、plurals）と smali の選択文字列の自動翻訳;
  • 資源（strings、arrays、plurals）と smali の手動翻訳;
  • 翻訳の修正;
  • 複数の翻訳サービスから選べるオンライン翻訳;
  • オフライン翻訳;
  • 辞書サポート;
  • 既存の翻訳から独自辞書を作成;
  • MT Manager 辞書のサポート;
  • 言語の結合。
    • アプリで使えるオンライン翻訳サービスはいくつですか？
    3つ: Yandex、Google、Bing。
    アプリの翻訳機能が見つかりません。Yandex.Translate を有効にしてアプリ（strings.xml）をロシア語に翻訳するには？
    この機能はアプリがデコンパイルされているときだけ使えます。
    1. 目的の apk の資源をデコンパイルします。
    2. デコンパイル済みファイルのフォルダーに移動します。
    3. ファイルマネージャーメニュー（アドレスバーをタップして開く）を開き、「翻訳」を選択します。
    アプリを自動翻訳するには？
    1. 目的の apk の資源をデコンパイルします。
    2. デコンパイル済みファイルのフォルダーに移動します。
    3. ファイルマネージャーメニュー（アドレスバーをタップして開く）を開き、「翻訳」を選び、右上の三点をタップして「自動翻訳」を選びます。
    4. 開いたメニューで目的の翻訳サービス、たとえば Yandex を選びます。
    5. 「ソース言語」では「言語を検出」のままで構いません。最終言語の自動選択では目的の言語を選びます。既定ではシステムに入っている言語が提案されます。
    6. 下部で必要なチェック「存在すれば結合」または「翻訳済み文字列のみ保存」をオンにします
    7. 必要な行を選択します。
    8. 「翻訳」をタップして res/values/strings の文字列を翻訳します。
    9. 転送が終わったら、もう一度右上の三点をタップして「保存」を選びます
    10. プロジェクト（アプリ）をビルドします。
    smali 内のアプリを自動翻訳するには？
    1. 目的の apk をデコンパイルします。
    2. デコンパイル済みファイルのフォルダーに移動します。
    3. ファイルマネージャーメニュー（アドレスバーをタップして開く）を開き、「smali 翻訳」を選び、右上の三点をタップして「自動翻訳」を選びます。
    4. 開いたメニューで目的の翻訳サービス、たとえば Yandex を選びます。
    5. 「ソース言語」では「言語を検出」のままで構いません。最終言語の自動選択では目的の言語を選びます。既定ではシステムに入っている言語が提案されます。
    6. 必要な行を選択します。
    7. 下部で必要なチェック「存在すれば結合」または「翻訳済み文字列のみ保存」をオンにします
    8. 「翻訳」をタップ
    9. 転送が終わったら、もう一度右上の三点をタップして「保存」を選びます。
    10. プロジェクト（アプリ）をビルドします。
    「自動翻訳」に「翻訳を修正」機能があります。何のためですか？
    翻訳しなくてよい行をスキップするため: true, false, %1$d/%2$d。現在はベクターグラフィックや参照なども含み、自動翻訳後の一部の行も修正します。
    アプリを手動で翻訳するには？
    1. 目的の apk をデコンパイルします。
    2. デコンパイル済みファイルのフォルダーに移動します。
    3. ファイルマネージャーメニュー（アドレスバーをタップして開く）を開き、「smali 翻訳」を選んで必要な行を手動編集します。
    4. 右上の三点をタップして「保存」を選びます
    5. プロジェクト（アプリ）をビルドします。
    翻訳したアプリの既定文字列に必要なものがなく、ほかの言語にはある場合、言語を結合するには？
    必要な翻訳の後、翻訳メニューで「追加、次から追加」を選び、別のロケールから不足行を追加します。必要ならその後翻訳します。
    Apktool M がサポートする辞書形式は？
    *.amd と *.mtd
    翻訳済みファイルから独自辞書を作るには？
    Yandex.Translate を開き、メニューから「辞書を作成」を選び、プロジェクトフォルダーでソース（未翻訳文字列）とターゲット資源（翻訳ファイル）を選んで保存します。
    保存した辞書はどう使いますか？
    次に転送するとき、翻訳サービスの選択に表示されます。
    オフライン翻訳用の既製辞書はどこで入手できますか？
    次の場所: MT Manager トピック
    「出力ディレクトリ/dictionary」（既定は内部メモリの「Apktool_M/dictionary」）へコピーするか、プログラム内で辞書ファイルをタップしてインポートし追加します。
    その後、辞書は Yandex.Translate の自動翻訳サービスに表示されます。
    転送後、プロジェクトが集まりません。エラーが返ります。
    1. ビルドエラーログに通常示される無効な行を削除します。
    2. aapt2 でビルドできず、無効な翻訳文字列のエラーもなければ、ビルドには aapt1 を使います。
    3. アプリが署名で保護されている可能性があります。
    Antisplit 機能
    Antisplit とは何ですか？
    Android App Bundle（split）を 1 つのインストールファイルに結合し、そのようなファイルのインストールと抽出も行う機能です。
    split から apk をビルドするには？ このオプションはどこにありますか？
    1. コンテキストメニュー「Antisplit」。apks/xapk の短いタップで呼び出します。
    2. コンテキストメニュー「Antisplit」。事前選択／選択した apk のグループをタップして呼び出します。
    次に必要なコンパイルツールを選びます: アプリが最初にビルドされない場合は aapt2 または aapt。
    インストール済み split から apk をビルドできますか？
    はい。
    アプリ一覧でインストール済みアプリを選び、長押しで「Antisplit」項目を呼び出します。
    集めたファイルはどこにありますか？
    apk は既定の作業フォルダー internal_memory/Apktool_M にあります。
    ビルド終了時に「インストール」ボタンが出ますが、長押しするとファイルのあるフォルダーが開きます。
    Apktool M で Apks を Apk に変換する手順。
    1. 目的のファイル（Apks）を選んでタップします。
    2. 表示されたメニューから「Antisplit」を選びます。
    3. もう一度「Antisplit」ボタンをタップします（まずすべてのファイル、つまりすべてのチェックがオンか確認します）。
    4. その後、目的のツール（アプリがコンパイルされない場合は aapt2 または aapt）を選び、「選択」ボタンをタップします。
    5. 処理全体が終わるまで待ちます。
    これで Apks が Apk になり、通常の Apk ファイルとして扱えます。
    カスタム署名の作成
    自分の署名を作るには？

    「設定」→「署名」に行き、「キーを作成」を選びます。

  • 署名設定では RSA/SF ファイル名と、V1 署名の作成者名を設定できます

    • 開いたメニューで次の行を入力します:

    署名アルゴリズム:
    証明書ハッシュの長さの違い（apk 署名後）。SHA256withRSA が最適です。既定のままにします。MD5 は安全でないとされます。詳細な違いはインターネットで確認できます。

    種類:
    ストレージの種類を指定します。既定は JKS（.keystore としても知られます）。詳細な違いはインターネットで確認できます。

    キーへのパス:
    キーの出力保存場所です。ファイル名は自動入力され、最後に変更できます。

    エイリアス:
    キーのエイリアス。インポート／操作時に指定します。

    ストレージとキーのパスワード:
    インポート／使用前にストレージとキー自体を保護するパスワードです。便宜上、同じにしても構いません。

    キーサイズ:
    読み取るキー署名のビット数（長さ）です。既定値は 2048 です。大きくすると暗号強度は上がりますが、解析は難しく（遅く）なります。幾何数列（2、4、8、16、32、64、128、256、512、1024、2048、4096 など）で設定します

    有効期間:
    作成日からキーの真正性が切れるまでの時間です。年単位で指定します。

    次の情報は署名所有者の案内用です。任意で指定してください:
    名前、役職、組織、市区町村、地域／州、国。

    「保存」ボタンで作成を完了し、先に指定したパスにキーストアを置きます。

    「作成して使用」ボタンは、最終ファイルをユーザー署名の代わりに追加インポートします。

    jks/keystore リポジトリを pk8+x509.pem に変換できますか？
    はい、可能です。
    ファイルマネージャー
    Apktool に本格的なファイルマネージャーはありますか？
    はい。
    ファイルマネージャーメニューを開くには？
    アドレスバーをタップするとメニューが開きます。
    どのような機能がありますか？
  • ファイルの削除;
  • コピー;
  • 名前の変更（一括変更を含む）;
  • ファイル一覧の作成;
  • アーカイブ;
  • ファイルとフォルダーのプロパティ;
  • 本格的な検索;
  • ブックマーク;
  • 最近開いたファイルの履歴;
  • apk/apks ファイルのプロパティダイアログは別トピックです;
  • ベクター xml/svg のプレビュー、および画像のベクター変換;
  • ttf/otf フォントのプレビュー;
  • 選択した apk や画像の一括操作（長押し）;
  • プロジェクトフォルダーでは、資源ファイルのプロパティに public.xml の ID があります（あれば）。
    • ファイル閲覧時にコンテキストメニューを開くには？
    ファイル自体を長押しします。
    コンテキストメニューにどの項目がありますか？
  • ファイルを送信...
  • 次で開く...
  • 削除。
  • 名前を変更。
  • 圧縮。
  • ここに展開。
  • 「ファイル名」へ展開
  • 内容を表示。
  • プロパティ。
  • コピー。
  • 切り取り。
  • MPatcher.
  • 選択。
  • すべて選択。
  • 名前をコピー。
  • パスをコピー。
  • ブックマークに追加。
    • ファイル／フォルダーを選択するには？
    1. ファイル／フォルダー自体またはアイコンを長押しします。
    2. アイコンの長押しでファイル／フォルダーを選んだ後、別ファイルのアイコンを長押しすると「から〜まで」を選択できます。
    3. 「戻る」アイコン（..）の長押しですべてをすばやく選択することもできます
    ファイルの名前を変更するには？
    ファイルを長押しすると名前変更ダイアログが出ます。
    同じダイアログで「auto」を長押しすると、テンプレートで自動モードの名前変更ができます。
    アプリから直接、外部エディタでファイルを編集するには？
    ファイルを長押し → ポップアップのコンテキストメニューで「次で開く」...
    ファイルのアーカイブを作るには？
    コンテキストメニューから「圧縮」を選びます。アーカイブ時、既存アーカイブに追加できます。
    分解／組み立てせずに、アーカイブ（APK を含む）内のファイル／フォルダーを削除または置換できますか？
    はい。
    1. /.apk アーカイブを長押しし、ポップアップメニューから「内容を表示」を選びます。
    2. 削除または抽出したいものを長押しで選びます。
    必要な操作の後、ファイルは自動的に再組み立てされ署名されます。
    元のファイルは横に .bak 拡張子で保存されます。
    分解済み APK で、すでに編集したファイルやフォルダーに置き換えるには？
    目的のファイルを長押しし、コンテキストメニューで「ここに展開」...
    たとえば drawable フォルダーの画像を置き換える場合、画像を含む drawable フォルダーが入った置換用 res フォルダーを apk に追加する必要があります。

    つまり、ディレクトリ構造を保つことが重要です！

    必要な操作の後、apk 拡張子で再びアーカイブします。
    署名します。
    Apktool M に本格的な検索エンジンはありますか？
    はい。
    ファイル検索、ファイル名、ファイル内テキスト検索、インストール済みアプリがあります。
    アドレスの手動入力は、アドレスの長押しで起動します。
    アプリに正規表現検索はありますか？
    はい。
    検索を使い始めるには？
    アドレスをタップしてファイルマネージャーメニューを開きます。
    フォルダー検索が見つかりません。ファイル内だけです。
    フォルダー自体を長押しするのではなく、検索するフォルダーに入り、「矢印またはフォルダー／ファイルへのパス」をタップすると検索メニューが出ます。
    検索結果はすべて保存されますか？ どう探せばよいですか？
    はい。検索履歴は保存されます。
    エクスプローラーメニュー（上部のアドレスをタップ）に項目が出るか、下部パネルの検索アイコンが有効ならそれを長押しします。
    検索結果の中をさらに検索することもできます。
    何も検索していなければ、この項目はありません。

    Apktool M を更新するには？

    MPatcher
    MPatcher とは何ですか？
    Shell で書かれたスクリプトとパッチを実行、作成、インポート、エクスポートするアプリで、Apktool M に統合されています。
    フォーラムに別トピックはありますか？
    はい: MPatcher
    MPatcher を呼び出すには？
    ファイルを長押しし、開いたコンテキストメニューで「MPatcher」を選びます。
    これで対象 apk が指定されます。

    対象プロジェクトを選ぶには、「ビルド」の上にドロップダウンメニューがあり、MPatcher 項目があります。
